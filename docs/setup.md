# Установка и запуск LD LATTE

### Требования

- Node.js и npm.
- Проект Supabase.
- n8n для Telegram-автоматизации.
- Telegram-бот, созданный через BotFather.

### Шаг 1. Клонирование репозитория

```bash
git clone https://github.com/Anasikus/ld-latte-automation.git
cd ld-latte-automation
```

### Шаг 2. Установка зависимостей

```bash
npm install
```

### Шаг 3. Настройка Supabase

Создайте новый проект в [Supabase](https://supabase.com/).

В SQL Editor последовательно выполните:

1. [`supabase/schema.sql`](../supabase/schema.sql) — создание таблиц и настройка RLS.
2. [`supabase/seed.sql`](../supabase/seed.sql) — добавление демонстрационных услуг.

SQL-файлы предназначены для нового проекта Supabase. `schema.sql` восстановлен по отчёту о текущей БД; оригинальное тело функции `is_app_admin()` и полные GRANT-настройки не входили в отчёт, поэтому реализация функции и права на `app_admins` предложены как безопасный эквивалент. Перед production-развёртыванием требуется проверка. Не следует выполнять их повторно в существующей рабочей базе без проверки.

**Основные таблицы:**

| Таблица | Назначение |
|---|---|
| `requests` | Пользовательские заявки |
| `services` | Услуги Telegram-бота |
| `app_admins` | Список пользователей с правами администратора |

Таблица `requests` связана с Supabase Authentication через `user_id`.

Политики RLS ограничивают доступ пользователей к собственным заявкам. Для `services` разрешено публичное чтение только активных услуг. Администратор может просматривать все услуги, добавлять и редактировать их через политики RLS. Прямой доступ клиентов к `app_admins` закрыт.

Чтобы назначить администратора, сначала зарегистрируйте пользователя через Supabase Auth, затем в **SQL Editor** выполните (подставив его UUID из Authentication → Users):

```sql
insert into public.app_admins (user_id)
values ('YOUR_AUTH_USER_UUID');
```

Не выполняйте этот запрос в браузерном приложении и не добавляйте UUID реального пользователя в публичный seed.

### Включение удаления в существующей базе Supabase

После обновления фронтенда в **SQL Editor того же проекта Supabase** один раз выполните [`supabase/migrations/20261031_admin_deletion.sql`](../supabase/migrations/20261031_admin_deletion.sql). Перед применением рекомендуется сделать резервную копию таблиц. **Не запускайте** заново `supabase/schema.sql` в существующей базе — это схема для нового проекта.

Миграция выдаёт право `DELETE` роли `authenticated` вместе с RLS, которая разрешает:

- удалять **собственные заявки** только администраторам, указанным в `app_admins`;
- удалять **услуги каталога** только администраторам;
- обычным пользователям удаление запрещено, включая прямые запросы через REST API.

Администраторы по-прежнему видят только собственные заявки: остальные пользователи и их данные изолированы существующей SELECT-политикой. Удаление необратимо и требует подтверждения в интерфейсе. Для контрольной проверки воспользуйтесь [чек-листом](testing/admin-delete-manual-checklist.md).


В настройках Supabase Authentication необходимо включить Email Authentication и при необходимости настроить подтверждение электронной почты.

### Шаг 4. Переменные окружения

Создайте файл `.env.local` в корне проекта:

```env
VITE_SUPABASE_URL=YOUR_SUPABASE_URL
VITE_SUPABASE_PUBLISHABLE_KEY=YOUR_SUPABASE_PUBLISHABLE_KEY
```

Значения доступны в настройках проекта Supabase.

Используется публичный Publishable Key. Секретные ключи Supabase нельзя добавлять в клиентские переменные `VITE_`.

### Шаг 5. Локальный запуск

```bash
npm run dev
```

Откройте адрес, указанный Vite в терминале.

### Шаг 6. Настройка Telegram-бота в n8n

1. Создайте бота через BotFather.
2. Импортируйте [`n8n/telegram-services.json`](../n8n/telegram-services.json) в n8n.
3. Подключите Telegram Credentials к Telegram Trigger.
4. В обоих узлах Supabase REST API укажите URL проекта и Publishable Key.
5. В HTTP-узлах `sendMessage` и `answerCallbackQuery` укажите свой токен Telegram Bot API; в узле Telegram `Send Selected Service` выберите Telegram Credentials. В `Additional Fields` для него отключена `Append n8n Attribution`.
6. Проверьте параметры JSON Body.
7. Опубликуйте workflow.

После публикации отправьте боту `/start` и проверьте получение списка услуг.

Для самостоятельной работы Telegram Trigger необходим доступный извне HTTPS webhook n8n.

**Безопасность:** не публикуйте реальные токены Telegram, секретные ключи Supabase или файлы с приватными данными.
### Быстрая проверка бота

1. Отправьте `/start` и сравните число кнопок с числом активных услуг.
2. Выберите кнопку: бот должен отправить название услуги в чат.
3. Переименуйте, добавьте и отключите услугу. Повторный `/start` должен показать актуальные данные.
4. Отключите все услуги — бот должен показать сообщение без клавиатуры.

Для импорта используйте актуальный файл [`n8n/telegram-services.json`](../n8n/telegram-services.json). Заполнители URL и токенов заменяйте в собственной среде n8n, без публикации секретов в Git.
