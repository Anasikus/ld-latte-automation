# Ручная проверка удаления заявок и услуг

Статус: **NOT RUN** — сценарии необходимо выполнить после применения SQL-миграции к тестовой Supabase БД. Чек-лист не является отчётом о выполненных тестах.

## Подготовка

1. Сохранить текущие тестовые записи или сделать резервную копию таблиц.
2. Выполнить [SQL-миграцию](../../supabase/migrations/20261031_admin_deletion.sql) в тестовой Supabase.
3. Подготовить администратора (запись в `app_admins`) и обычного пользователя.
4. Для каждого пользователя создать отдельную заявку; для каталога подготовить тестовую услугу.

| № | Проверка | Ожидаемый результат |
|---|---|---|
| DEL-01 | Открыть «Мои заявки» под администратором | На собственных карточках видна кнопка «Удалить» |
| DEL-02 | Нажать «Удалить» для заявки, затем «Отмена» / Escape | Диалог закрывается, заявка остаётся |
| DEL-03 | Подтвердить удаление заявки | После ответа API карточка исчезает, статистика пересчитывается, появляется toast |
| DEL-04 | Открыть каталог под администратором, отменить удаление услуги | Услуга остаётся в таблице и в Telegram при следующем `/start` |
| DEL-05 | Подтвердить удаление тестовой услуги | Запись исчезает, количества пересчитываются; новый `/start` не показывает услугу |
| DEL-06 | Открыть «Мои заявки» под обычным пользователем | Кнопки удаления нет; другие пользователи и их заявки не видны |
| DEL-07 | Под обычным пользователем отправить прямой REST DELETE для своей заявки и услуги | RLS не даёт удалить запись, проверка повторным SELECT подтверждает её существование |
| DEL-08 | Попробовать удалить неизвестный ID или получить ошибку сети | Нет ложного сообщения об успехе, пользователь видит понятный toast |
| DEL-09 | Проверить карточки и диалоги на узком экране | Кнопки доступны, диалог и увеличенный текст не выходят за границы |

**Важно:** тестировать удаление в рабочей базе исключительно на специально созданных тестовых данных. Само наличие SQL-файла в GitHub не применяет миграцию к Supabase автоматически.
