# Проверка прав удаления заявок и услуг

**Статус: NOT RUN.** Эти проверки нужно выполнить на тестовых записях после применения SQL-миграции в тестовом Supabase. Коммит и PR не применяют SQL к базе автоматически.

| ID | Пользователь и действие | Ожидаемый результат |
| --- | --- | --- |
| DEL-01 | Обычный пользователь открывает собственную заявку | Кнопка «Удалить» доступна |
| DEL-02 | Обычный пользователь нажимает удаление, затем «Отмена» или Escape | Заявка остаётся |
| DEL-03 | Обычный пользователь подтверждает удаление своей тестовой заявки | Запись исчезает только после ответа API; появляется toast; статистика обновляется |
| DEL-04 | Пользователь пытается DELETE чужой заявки через Supabase REST API | Чужая запись не удаляется благодаря RLS |
| DEL-05 | Обычный пользователь пытается открыть вкладку услуг напрямую | Доступ к административному каталогу отсутствует |
| DEL-06 | Обычный пользователь пытается DELETE тестовой услуги через REST API | RLS не позволяет удалить услугу |
| DEL-07 | Администратор открывает каталог, отменяет удаление услуги | Услуга сохранена |
| DEL-08 | Администратор подтверждает удаление тестовой услуги | Запись удалена; счётчики обновились; после `/start` Telegram не предлагает удалённую услугу |
| DEL-09 | Удаление с ошибкой сети или несуществующим ID | Ошибка показывается через toast; ложного сообщения об успехе нет |
| DEL-10 | Узкий экран телефона | Диалог и кнопки доступны, элементы не выходят за границы карточки |

**Перед запуском:** сделать резервную копию тестовых данных; проверить существующие RLS DELETE-политики на обеих таблицах в Supabase, затем применить `supabase/migrations/20261031_owner_and_admin_deletion.sql`. Не запускать `supabase/schema.sql` в существующей базе. Проверка удаления необратима.
