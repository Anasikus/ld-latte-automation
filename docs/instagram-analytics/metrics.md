# Матрица метрик Instagram

**Важно:** ниже перечислены предполагаемые семейства методов, а не гарантия поддержки для каждого аккаунта. Доступность параметров зависит от выбранного Instagram API (Instagram Login / Facebook Login), версии Graph API, разрешений, типа медиа и типа аккаунта. Для реализации сверить Meta Docs и ответы тестовых запросов.

| Метрика | Предполагаемый метод | Предпосылки | Период/частота | Ограничения и проверка |
|---|---|---|---|---|
| Подписчики (`followers_count`) | Получение полей профиля IG user | Профессиональный аккаунт, разрешение чтения профиля | Снимок ежедневно | Это текущее число, не историческая динамика; историю накапливаем сами |
| Охват аккаунта (`reach`) | IG user insights | Разрешение на insights | Период, поддерживаемый API; ежедневно | Уникальные аккаунты; не суммировать как обычные просмотры |
| Просмотры аккаунта (`views`) | IG user insights | Insights + поддержка метрики | Поддерживаемый API период | Возможны изменения названий/доступности по версии API |
| Вовлечённость аккаунта (`accounts_engaged` и др.) | IG user insights | Insights | Поддерживаемый API период | Уточнить определение и совместимость метрики |
| Список публикаций | IG user media edge | Доступ к медиа | Новые публикации ежедневно, с пагинацией | Не все виды контента и поля одинаково доступны |
| Тип, дата, permalink публикации | Поля media object | Доступ к медиа | При обнаружении и периодическом обновлении | Набор полей зависит от media type |
| Просмотры публикации (`views`) | Media insights | Insights + поддерживаемый media type | Ежедневный снимок для новых публикаций | Может отсутствовать у некоторых типов медиа; не подменять `plays`/`impressions` |
| Охват публикации (`reach`) | Media insights | Insights | Повторный снимок | Доступность зависит от типа медиа |
| Лайки (`like_count`) | Media object или media insights — проверить для flow | Доступ к медиа | Снимок | Уточнить точный источник и ограничения |
| Комментарии (`comments_count`) | Media object или media insights — проверить для flow | Доступ к медиа | Снимок | Не считать число комментариев эквивалентом уникальных авторов |
| Сохранения (`saved`) | Media insights | Insights, подходящий media type | Снимок | Может быть недоступно; `NULL`, не `0` |
| Репосты (`shares`) | Media insights | Insights, подходящий media type | Снимок | Может быть недоступно; уточнить доступность |

## Методика верификации
1. Зафиксировать API flow и версию.
2. Для каждого показателя выполнить тестовый запрос к реальному профессиональному тестовому аккаунту.
3. Сохранить пример успешного JSON, HTTP status и описание ошибки, если метрика недоступна.
4. Сопоставить значения и периоды с интерфейсом Instagram Insights с учётом задержки обновления и временных зон.
5. Обновить матрицу: **подтверждено / недоступно / требует проверки**. Только подтверждённые метрики включать в обязательный SLA.

## Семантика данных
- `0` — API вернул числовой ноль.
- `NULL` + `unavailable_reason` — API не вернул значение / нет разрешения / неподдерживаемая метрика.
- `collected_at` — когда запрос выполнен; `period_start/end` — к какому интервалу относятся данные; не путать.
- Для счётчиков публикаций сохранять последовательность снимков, чтобы видеть динамику.
- При изменении версий API фиксировать `source_api_version` и изменения определения метрики.

## Конкретизация доступных периодов: план верификации

Варианты `period` ниже — **пробные сочетания**, а не универсальная гарантия Meta API. Поддержку нужно подтверждать для выбранной версии API, типа аккаунта и OAuth flow.

| Метрика | Начальные параметры проверки | Ограничения и действия |
|---|---|---|
| `followers_count` (профиль) | Получение поля профиля, без `period`; ежедневный снимок | Не является готовой историей; динамика накапливается из снимков |
| `follower_count` (если доступна в insights) | `period=day` | Проверить требования по размеру аудитории и версии API |
| `reach` (аккаунт) | `day`, `week`, `days_28` | Проверить каждый вариант; уникальный охват дней нельзя складывать в недельный |
| `views` (аккаунт) | Начать с `period=day` и подходящего `metric_type` | Проверить возможные задержки и поддержку метода |
| `accounts_engaged` / `total_interactions` | Начать с `period=day`, `metric_type=total_value` | Проверить реальные поддерживаемые интервалы и группировки |
| `views`, `reach`, `saved`, `shares` (медиа) | Media insights, отдельно для фото, Reels, Story | Уточнить доступность по типу медиа, lifetime и окно хранения |

Сохранять `metric`, `period`, `metric_type`, `since/until` (только где поддерживается), UTC-время измерения и версию API. Не считать `impressions` и `plays` автоматически эквивалентными современной метрике `views`.

Пример **шаблона**, который требует проверки после выбора OAuth flow:

```text
GET /{ig-user-id}/insights?metric=reach,views&period=day&metric_type=total_value
```

Если общий запрос отклонён, проверять каждую метрику по отдельности и документировать HTTP-код/ответ. В рамках тестового задания реальные API-запросы к Instagram не выполнялись.
