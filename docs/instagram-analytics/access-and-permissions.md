# Подключение Instagram: права, роли, токены и проверка

**Статус:** проект реализации. Реальных аккаунтов, токенов и ответов API в рамках тестового задания нет.

## Два сценария OAuth

| Параметр | Instagram API with Instagram Login | Instagram API with Facebook Login |
|---|---|---|
| Тип аккаунта | Профессиональный Business / Creator | Профессиональный Business / Creator |
| Связь с Facebook Page | Не обязательна для этого сценария | Обязательна связь Instagram с Facebook Page |
| Кто авторизует | Владелец Instagram-аккаунта | Пользователь с необходимыми правами на связанную Page и бизнес-активы |
| Host | `graph.instagram.com` | `graph.facebook.com` |
| Права для аналитики | `instagram_business_basic`, `instagram_business_manage_insights` | `instagram_basic`, `instagram_manage_insights`, `pages_read_engagement`; для поиска страниц обычно `pages_show_list` |
| Доступ приложения | Standard Access для собственных допустимых тестовых аккаунтов; Advanced Access / App Review для сторонних по правилам Meta | Аналогичные проверки прав и App Review, зависящие от сценария |

Для предоставления роли через Business Manager Meta может потребовать дополнительные permissions (`ads_read` / `ads_management`): проверять применимость по актуальной документации. Права на публикации, сообщения и модерацию комментариев для задачи сбора статистики не запрашивать.

## Пошаговая последовательность

1. **Компания:** предоставляет список аккаунтов, тип каждого аккаунта, контакт владельца и список требуемых метрик. Для Facebook Login подтверждает связь профессионального Instagram с Facebook Page и наличие у авторизующего пользователя необходимых прав.
2. **Разработчик:** выбирает один OAuth flow; настраивает Meta App, роли тестировщиков, HTTPS redirect URI, требуемые permissions и при необходимости App Review.
3. **Владелец аккаунта:** самостоятельно проходит официальный Meta OAuth, выдаёт согласие на минимально необходимые разрешения; пароль разработчику не передаёт.
4. **Серверный обработчик:** проверяет OAuth `state`, принимает временный code, обменивает его на соответствующий токен, сохраняет в защищённом хранилище; секреты не попадают в клиент или Git.
5. **Разработчик:** выполняет запросы для проверки профиля, Instagram user ID, media list, account insights и media insights; для Facebook Login дополнительно проверяет связь Page через доступные поля `instagram_business_account` и права доступа.
6. **n8n:** по расписанию обходит реестр активных подключений, проверяет доступность токена, запрашивает статистику, нормализует периоды и сохраняет с `upsert` в Supabase. Неудачи записывает в журнал и уведомления.

## Жизненный цикл токенов

Срок жизни токена и доступность обмена/обновления зависят от выбранного flow. После авторизации нужно сохранить тип токена, дату истечения, аккаунт и статус подключения. Поддерживаемые механизмы обновления выполнить сервером; отзыв прав, истечение и отказ от обновления переводят подключение в `reconnect_required` и требуют нового OAuth от владельца. На 401/403 не делать бесконечных повторов; на 429/5xx использовать ограниченный backoff и журнал диагностики.

## План первой проверки

- Проверить, что вернулись данные **нужного** аккаунта, и получить его ID.
- Проверить каждое permission, выбранную версию Graph API и первую метрику `followers_count`, `reach` или `views`.
- Запросить публикации с пагинацией и отдельную метрику поста/Reels. Зафиксировать реальные `period`, `metric_type`, пределы и ошибки.
- Подключить второй тестовый аккаунт, проверить разделение данных и повторную синхронизацию без дубликатов.
- Сравнить результаты с Instagram Insights с учётом задержки и часовых поясов.

**Ограничение:** список разрешений и параметров требует сверки с актуальной версией Meta API и фактическими ответами.
