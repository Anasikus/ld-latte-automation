# Пошаговый план внедрения и ответственность

| Этап | Владелец аккаунта | Технический специалист | Автоматизация |
|---|---|---|---|
| 1. Подготовка | Подтверждает, что аккаунт профессиональный, согласует метрики и доступ | Выбирает OAuth flow, создаёт/настраивает Meta App, проверяет доступ и app review | — |
| 2. Подключение | Авторизуется через официальный Meta OAuth, подтверждает разрешения | Реализует callback, хранение токена и реестр аккаунтов | Сохраняет технический статус подключения |
| 3. Проверка API | При необходимости подтверждает права/переподключает | Проверяет токен, ID аккаунта, endpoint и версии API | Пробный запрос и запись диагностики |
| 4. Сбор | — | Настраивает n8n, пагинацию, лимиты, маппинг | По расписанию получает профиль, insights и медиа |
| 5. Сохранение | — | Создаёт таблицы, уникальные ключи, RLS, индексы | Нормализует и делает upsert |
| 6. Контроль | Подтверждает ожидаемые цифры в Instagram Insights | Сравнивает результаты, документирует расхождения | Логирует ошибки, повторы, уведомления |
| 7. Эксплуатация | Переподключает при отзыве доступа | Мониторит версии API и разрешения | Выполняет синхронизацию и уведомляет о сбоях |

## Конкретная последовательность
1. Уточнить количество аккаунтов, владельцев, типы профилей, нужные KPI и допустимую задержку данных.
2. Проверить актуальную документацию Meta по **выбранной версии** API и доступности Instagram Login / Facebook Login.
3. Создать Meta App, настроить OAuth redirect URI, запросить минимальные разрешения, определить необходимость Advanced Access / App Review.
4. Подключить один тестовый профессиональный аккаунт; получить его идентификатор и выполнить минимальные запросы.
5. Утвердить матрицу реально доступных метрик и периоды; зафиксировать отличия по типам публикаций.
6. Создать таблицы Supabase и ограничения уникальности, политики доступа, безопасное хранение ссылок на токены.
7. Реализовать n8n workflow: schedule → connections → loop → HTTP → normalize → upsert → log.
8. Добавить пагинацию, контроль лимитов, экспоненциальные повторы и остановку при ошибках авторизации.
9. Проверить 2–3 аккаунта, повторную синхронизацию, пропуски данных и несовпадение временных зон.
10. Согласовать отчётный формат, запустить мониторинг, описать регламент переподключения и обслуживания.

## Безопасность
- OAuth access token и app secret не отправлять в клиентский код, URL публичных страниц, Git или обычные логи.
- Использовать серверное секретное хранилище / шифрование и минимально необходимые права.
- Проверять `state` при OAuth и защищать callback от CSRF.
- Разграничивать доступ сотрудников к аналитике разных клиентов; не смешивать tenant/connection ID.
- Не предоставлять браузеру `service_role` ключ Supabase.
- Для production предусмотреть ротацию/отзыв токенов и процедуру удаления данных по запросу владельца.

## Критерий завершения проектирования
Выбран поддерживаемый OAuth flow; подтверждён список метрик и периодов пробными запросами; согласована схема хранения и частота сбора; есть тест-план, регламент ошибок и список открытых вопросов.
