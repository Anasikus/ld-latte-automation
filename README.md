# LD LATTE — Automation Test Assignment

Тестовое задание по автоматизации бизнес-процессов с использованием **n8n, React, TypeScript и Supabase**.

Проект включает три части:

1. Telegram-бот с динамическим списком услуг.
2. Веб-приложение для управления пользовательскими заявками.
3. Технический план интеграции Instagram Direct через Meta API.

## 1. Telegram-бот — n8n + Supabase

Telegram-бот предоставляет актуальный список услуг и позволяет пользователю выбрать интересующую услугу с помощью inline-кнопок.

### Реализованные возможности

- Автоматическая обработка команды `/start`.
- Получение активных услуг из Supabase REST API.
- Динамическое формирование inline-клавиатуры.
- Обработка событий `callback_query`.
- Проверка актуальности выбранной услуги.
- Отображение уведомления с названием услуги.
- Обработка отсутствия активных услуг.
- Обновление списка без изменения кода workflow.

### Архитектура

```text
Telegram Trigger
       |
     Switch
       |
       +-- /start
       |      |
       |   Supabase REST API
       |      |
       |   Code: формирование кнопок
       |      |
       |   Telegram sendMessage
       |
       +-- callback_query
              |
           Supabase REST API
              |
           Code: проверка услуги
              |
           Telegram answerCallbackQuery
```

Данные загружаются из Supabase при каждом вызове `/start`. При выборе услуги бот дополнительно проверяет, остаётся ли она активной.

### Тестирование

| Сценарий | Результат |
|---|---|
| 0 активных услуг | Сообщение об отсутствии услуг |
| 2 активные услуги | Две inline-кнопки |
| 5 активных услуг | Пять inline-кнопок |
| 9 активных услуг | Девять inline-кнопок |
| Выбор активной услуги | Уведомление с названием услуги |

Все перечисленные сценарии проверены вручную.

### Экспорт workflow

Файл: [`n8n/telegram-services.json`](./n8n/telegram-services.json)

Экспорт содержит узлы, условия маршрутизации, JavaScript-код и связи между узлами.

Токены и параметры подключений заменены заполнителями. Для запуска необходимо указать собственные значения.

Веб-приложение предназначено для создания и управления пользовательскими заявками.

### Реализованные возможности

- Регистрация и авторизация.
- Сохранение пользовательской сессии.
- Выход из аккаунта.
- Защищённые маршруты.
- Создание и редактирование заявок.
- Просмотр списка заявок.

## 3. Instagram Direct — план интеграции Meta API

**Статус: технический план. Интеграция не реализована.**

### Цель

Автоматизировать получение и обработку входящих сообщений Instagram Direct с использованием n8n и Supabase.

### Предлагаемая архитектура

```text
Instagram Direct
       |
Meta API / Webhooks
       |
HTTPS Webhook
       |
n8n: проверка и обработка события
       |
Supabase: сохранение сообщения
       |
Определение сценария ответа
       |
Instagram Send API
```

### Требования для подключения

1. Профессиональный Instagram-аккаунт (Business или Creator).
2. Приложение в Meta for Developers.
3. Настройка Instagram Login и необходимых разрешений, включая `instagram_business_basic` и `instagram_business_manage_messages`.
4. Получение и безопасное хранение access token.
5. Настройка HTTPS Webhook и подписки на события сообщений.
6. Проверка необходимых условий доступа Meta, включая App Review при работе со сторонними аккаунтами.

### Предполагаемый алгоритм

1. Пользователь отправляет сообщение в Instagram Direct.
2. Meta отправляет событие на Webhook.
3. n8n проверяет подлинность запроса.
4. Workflow извлекает идентификатор сообщения, отправителя и содержимое.
5. Проверяется наличие ранее обработанного сообщения.
6. Данные сохраняются в Supabase.
7. Определяется сценарий обработки: автоматический ответ или передача обращения оператору.
8. При необходимости ответ отправляется через Instagram API с соблюдением правил платформы.

### Безопасность и обработка ошибок

- Серверное хранение токенов и App Secret.
- Проверка подписи Webhook.
- Защита от повторной обработки событий.
- Логирование ошибок.
- Контролируемые повторные запросы.
- Соблюдение ограничений Instagram Messaging API.

### План тестирования

| Сценарий | Ожидаемый результат |
|---|---|
| Новое сообщение | Сохранение в Supabase |
| Повторный Webhook | Отсутствие дубликатов |
| Сообщение с вложением | Корректная обработка типа сообщения |
| Недействительный токен | Обработка ошибки авторизации |
| Ошибка API | Логирование и контролируемый повтор |
| Некорректная подпись | Отклонение запроса |

Документация: [Instagram API — Meta](https://www.postman.com/meta/instagram/documentation/6yqw8pt/instagram-api).

## 5. Установка и запуск

### Требования

- Node.js и npm.
- Проект Supabase.
- n8n для Telegram-автоматизации.
- Telegram-бот, созданный через BotFather.

### Шаг 1. Клонирование репозитория

```bash
git clone https://github.com/Anasikus/ld-latte-automation.git
cd ld-latte-automation
```

### Шаг 2. Установка зависимостей

```bash
npm install
```

### Шаг 3. Настройка Supabase

Создайте новый проект в [Supabase](https://supabase.com/).

В SQL Editor последовательно выполните:

1. [`supabase/schema.sql`](./supabase/schema.sql) — создание таблиц и настройка RLS.
2. [`supabase/seed.sql`](./supabase/seed.sql) — добавление демонстрационных услуг.

SQL-файлы предназначены для нового проекта Supabase. Не следует выполнять их повторно в существующей рабочей базе без проверки.

**Основные таблицы:**

| Таблица | Назначение |
|---|---|
| `requests` | Пользовательские заявки |
| `services` | Услуги Telegram-бота |

Таблица `requests` связана с Supabase Authentication через `user_id`.

Политики RLS ограничивают доступ пользователей к собственным заявкам. Для `services` разрешено публичное чтение только активных услуг.

В настройках Supabase Authentication необходимо включить Email Authentication и при необходимости настроить подтверждение электронной почты.

### Шаг 4. Переменные окружения

Создайте файл `.env.local` в корне проекта:

```env
VITE_SUPABASE_URL=YOUR_SUPABASE_URL
VITE_SUPABASE_PUBLISHABLE_KEY=YOUR_SUPABASE_PUBLISHABLE_KEY
```

Значения доступны в настройках проекта Supabase.

Используется публичный Publishable Key. Секретные ключи Supabase нельзя добавлять в клиентские переменные `VITE_`.

### Шаг 5. Локальный запуск

```bash
npm run dev
```

Откройте адрес, указанный Vite в терминале.

### Шаг 6. Настройка Telegram-бота в n8n

1. Создайте бота через BotFather.
2. Импортируйте [`n8n/telegram-services.json`](./n8n/telegram-services.json) в n8n.
3. Подключите Telegram Credentials к Telegram Trigger.
4. В обоих узлах Supabase REST API укажите URL проекта и Publishable Key.
5. В узлах `sendMessage` и `answerCallbackQuery` настройте собственный токен Telegram Bot API.
6. Проверьте параметры JSON Body.
7. Опубликуйте workflow.

После публикации отправьте боту `/start` и проверьте получение списка услуг.

Для самостоятельной работы Telegram Trigger необходим доступный извне HTTPS webhook n8n.

**Безопасность:** не публикуйте реальные токены Telegram, секретные ключи Supabase или файлы с приватными данными.
